# 实测命令和证据记录

除基线固件外，使用 tools/console.py 发送测试帧。运行示例为 `python tools/console.py COM5 0x40 1`。以下 CMD 用十六进制，ARG 用十进制。保存发布提交号、板卡、接线、操作、预期、原始输出和视频文件名。

## 集中验收顺序

以下是剩余项目的执行顺序。下表保留历史记录，集中验收时另记实际固件提交、接线、原始输出与演示视频。步骤五独立固件可用于定位问题，F103 集成验收使用同一个集成 ELF。

1. 固定待验提交，在干净检出中运行主机检查、复核两板 CubeMX 再生成并构建 Debug。记录两板 Flash/RAM 和实际 ELF 路径。F407 先核对实板 HSE；当前 168 MHz 时钟树按 8 MHz 晶振配置。
2. 打开 [F103 集成 Ozone 工程](../boards/f103/f103.jdebug)，记录下载和启动日志。先做串口、TIM2 和任务资源检查，再采集 MPU6050 阻塞/中断数据、错误和恢复，随后检查 OLED 的四角和传感器条形图。两路 SG90 在这一轮单独接电复测，保留接触间歇的原记录。
3. 使用同一 F103 固件验证 CAN 回环，再接 USB-CAN 验证标准 ID `0x321`、`0x322` 双向传输、无应答与恢复。验证过滤器时先排空接收队列，让对端只发扩展帧或远程帧，接收应超时；随后发送标准数据帧 `0x322`，记录实际收到的 ID、DLC 和数据。
4. 打开 [F407 移植 Ozone 工程](../boards/f407/f407.jdebug)，运行共用的串口和 TIM2 流程。两板分别保存 Ozone 下载日志及串口记录。将新增的实测数据、视频和结论回填本表，并更新 roadmap。

脚本的命令号采用带 `0x` 的十六进制写法，例如 `python tools/console.py COM4 0x42 0`。串口助手使用 HEX 发送时，输入完整的四字节帧。

## 已执行的软件检查

从仓库根目录运行 `./tests/run.ps1`。Windows 原生 g++ 编译并运行了 68 项 UART/校验帧、43 项定时器/舵机和 153 项设备检查，全部通过。设备用例用模拟 I²C 寄存器检查 AD0、身份拒绝、补码与量程换算，用模拟 SPI 捕获八个显示页并检查边框和条形图，用边界帧检查 CAN 的 ID 与 DLC。物理时序、总线应答和屏幕方向仍由上表的实物用例验证。

## 两板集成固件构建

固件源码为 `b172010`。在各自板目录用 Arm GNU 14.3.1、CMake 和 Ninja 分别配置 Debug、Release，均用 `cmake --build --preset <预设名> --clean-first` 完整编译并链接。各工程的 Ozone 入口默认加载 Debug ELF。

| 目标 | 构建预设 | 链接器 Flash 占用 | 链接器 RAM 占用 | Debug 固件（相对于仓库） |
| --- | --- | --- | --- | --- |
| F103C8T6 完整框架 | Debug、Release 均成功 | 44256 / 65536 B | 18384 / 20480 B | `boards/f103/build/Debug/f103.elf` |
| F407ZGT6 串口与 TIM2 移植 | Debug、Release 均成功 | 22476 / 1048576 B | 16744 / 131072 B，另有 CCMRAM 使用 0 B | `boards/f407/build/Debug/f407.elf` |

两种预设的 C/C++ 均使用体积优化，Debug 保留调试信息。表中 RAM 来自链接器分区统计。最终验收时另行采集任务栈高水位和运行期剩余堆，核对 F407 实板晶振，并从干净检出复核构建。
